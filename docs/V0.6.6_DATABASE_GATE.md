# بوابة قاعدة البيانات — YSD AI v0.6.6

خطوات التطبيق اليدوي لترحيلَي `0017` و`0018` بالترتيب، مع التحقق والتراجع.

> **من ينفّذها**: أنت، من محرّر SQL في لوحة Supabase. الكود لا يملك صلاحية DDL
> (لا `SERVICE_ROLE` في `.env.local` ولا Supabase CLI مربوط) — وهذا مقصود.
>
> **قبل التطبيق**: الكود يعمل بلا الجدولين. عند غيابهما يسقط تلقائيًا إلى ذاكرة
> الخادم (`42P01`)، فلا تنكسر المحادثة ولا اللوحة. التطبيق يرفع الحماية من
> «داخل النسخة» إلى «عبر النسخ ودائمة».

## 0) نسخة احتياطية / لقطة مخطّط — قبل أي شيء

Supabase Dashboard ← **Database ← Backups** ← تأكّد من وجود نسخة اليوم.
مشاريع Pro: أنشئ **Point-in-Time Recovery** أو نسخة يدوية.

ولقطة مخطّط سريعة للمقارنة بعد التطبيق:

```sql

select table_name, column_name, data_type
from information_schema.columns
```

## 1) SQL النهائي — `0017_chat_request_ids`

```sql
create table if not exists public.chat_request_ids (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  client_request_id text not null
    constraint chat_request_ids_format check (client_request_id ~ '^[A-Za-z0-9_-]{8,64}$'),
  conversation_id uuid references public.conversations(id) on delete cascade,
  user_message_id uuid references public.messages(id) on delete set null,
  status text not null default 'in_progress'
    check (status in ('in_progress', 'completed', 'failed')),
  created_at timestamptz not null default now(),
  expires_at timestamptz not null default now() + interval '24 hours',
  constraint chat_request_ids_unique unique (user_id, client_request_id)
);

create index if not exists chat_request_ids_expires_idx
  on public.chat_request_ids (expires_at);
create index if not exists chat_request_ids_user_idx
  on public.chat_request_ids (user_id, created_at desc);

alter table public.chat_request_ids enable row level security;

drop policy if exists "chat_request_ids_select_own" on public.chat_request_ids;
create policy "chat_request_ids_select_own"
  on public.chat_request_ids for select
  using (auth.uid() = user_id);

drop policy if exists "chat_request_ids_insert_own" on public.chat_request_ids;
create policy "chat_request_ids_insert_own"
  on public.chat_request_ids for insert
  with check (auth.uid() = user_id);

drop policy if exists "chat_request_ids_update_own" on public.chat_request_ids;
create policy "chat_request_ids_update_own"
  on public.chat_request_ids for update
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

create or replace function public.cleanup_chat_request_ids()
returns integer
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  removed integer;
begin
  delete from public.chat_request_ids where expires_at < now();
  get diagnostics removed = row_count;
  return removed;
end;
$$;

comment on table public.chat_request_ids is
  'حجز معرّفات طلبات المحادثة لمنع الازدواج عبر نسخ الخادم. لا يحتوي أي نص رسائل.';
```

**لا سياسة `DELETE` عمدًا**: فلا يستطيع مستخدم حذف حجزه للتحايل على منع الازدواج.

## 2) SQL النهائي — `0018_observability_events`

```sql
create table if not exists public.observability_events (
  id bigserial primary key,
  created_at timestamptz not null default now(),
  mode text not null check (mode in ('general', 'protected')),
  error_code text check (error_code in (
    'provider_unavailable', 'network_error', 'auth_expired',
    'timeout', 'rate_limit', 'quality_guard', 'unknown'
  )),
  session_refresh_result text check (session_refresh_result in ('refreshed', 'failed', 'not_needed')),
  auth_ms integer not null default 0,
  conversation_lookup_ms integer not null default 0,
  user_message_insert_ms integer not null default 0,
  rag_ms integer not null default 0,
  provider_first_byte_ms integer not null default -1,
  total_first_text_ms integer not null default -1,
  total_response_ms integer not null default 0,
  provider_calls integer not null default 0,
  fallback_count integer not null default 0,
  protected_short_circuit boolean not null default false
);

create index if not exists observability_events_created_idx
  on public.observability_events (created_at desc);

alter table public.observability_events enable row level security;

drop policy if exists "observability_events_admin_read" on public.observability_events;
create policy "observability_events_admin_read"
  on public.observability_events for select
  using (public.is_admin());

-- تُزال السياسة المتساهلة إن كانت طُبّقت من نسخة سابقة
drop policy if exists "observability_events_insert" on public.observability_events;

revoke all on public.observability_events from anon, authenticated;
grant select on public.observability_events to authenticated;

create or replace function public.cleanup_observability_events()
returns integer
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  removed integer;
begin
  delete from public.observability_events where created_at < now() - interval '7 days';
  get diagnostics removed = row_count;
  return removed;
end;
$$;

comment on table public.observability_events is
  'مقاييس أداء المحادثة (أزمنة وعدّادات ورموز فقط). ممنوع حفظ أي نص أو بيانات شخصية.';
```

**لا سياسات `insert/update/delete` إطلاقًا**: مع تفعيل RLS، غياب السياسة = منع
تام لكل من `anon` و`authenticated`. الكتابة حصرًا من الخادم بـ`service_role`
(يتجاوز RLS) عبر `lib/supabase/admin.ts`.

## 3) استعلامات التحقق — بعد التطبيق

### وجود الجدولين
```sql
select table_name from information_schema.tables
where table_schema = 'public'
  and table_name in ('chat_request_ids', 'observability_events');
-- المتوقع: صفّان
```

### القيود
```sql
select conrelid::regclass as tbl, conname, contype, pg_get_constraintdef(oid) as def
from pg_constraint
where conrelid in ('public.chat_request_ids'::regclass, 'public.observability_events'::regclass)
order by tbl, conname;
-- تحقق من: chat_request_ids_unique (u) على (user_id, client_request_id)
--          chat_request_ids_format  (c) بنمط ^[A-Za-z0-9_-]{8,64}$
```

### الفهارس
```sql
select tablename, indexname, indexdef from pg_indexes
where schemaname = 'public'
  and tablename in ('chat_request_ids', 'observability_events')
order by tablename, indexname;
-- المتوقع: chat_request_ids_expires_idx · chat_request_ids_user_idx
--          observability_events_created_idx (+ مفاتيح أولية)
```

### RLS والسياسات
```sql
select relname, relrowsecurity from pg_class
where relname in ('chat_request_ids', 'observability_events');
-- المتوقع: relrowsecurity = true للاثنين

select tablename, policyname, cmd, qual, with_check
from pg_policies
where schemaname = 'public'
  and tablename in ('chat_request_ids', 'observability_events')
order by tablename, policyname;
-- المتوقع: chat_request_ids → select/insert/update (3 سياسات، auth.uid() = user_id)
--          observability_events → select فقط (is_admin())، ولا insert/update/delete
```

### الدوال و search_path
```sql
select p.proname, p.prosecdef as security_definer, p.proconfig
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname in ('cleanup_chat_request_ids', 'cleanup_observability_events');
-- المتوقع: security_definer = true · proconfig يحوي search_path=public, pg_temp
```

### إثبات عدم تغيّر البيانات القائمة
```sql
select
  (select count(*) from public.conversations) as conversations,
  (select count(*) from public.messages)      as messages,
  (select count(*) from public.files)         as files,
  (select count(*) from public.profiles)      as profiles;
-- يجب أن تطابق أرقام الخطوة 0 حرفًا بحرف
```

### فحص القيد عمليًا (اختياري)
```sql
-- يجب أن يفشل: مسافات وعربية غير مسموحة
insert into public.chat_request_ids (user_id, client_request_id)
values (auth.uid(), 'مع مسافة');
-- المتوقع: new row violates check constraint "chat_request_ids_format"
```

## 4) إثبات idempotency بين خادمين

بعد التطبيق، شغّل نسختين من الصورة نفسها (3300 و3301) على Supabase نفسه، وأرسل
الطلب نفسه بالتزامن بنفس `client_request_id`، ثم:

```sql
select client_request_id, count(*) as reservations
from public.chat_request_ids
where client_request_id = 'المعرّف-المستخدم-في-الاختبار'
group by client_request_id;
-- المتوقع: 1

select count(*) as user_messages
from public.messages
where conversation_id = 'معرّف-المحادثة' and role = 'user';
-- المتوقع: 1
```

## 5) التراجع — احذر

```sql
-- ⚠️ تحذير: لا تُشغَّل بعد بدء الاعتماد على الجدولين إلا بقرار صريح.
-- إسقاط chat_request_ids يُلغي منع الازدواج عبر النسخ، فتعود الحماية إلى
-- ذاكرة كل حاوية وحدها. وإسقاط observability_events يمحو تاريخ المقاييس نهائيًا.
-- لا يمسّ هذا التراجع أي محادثة أو رسالة أو ملف — الجدولان جديدان ومستقلان.

drop function if exists public.cleanup_chat_request_ids();
drop function if exists public.cleanup_observability_events();
drop table if exists public.chat_request_ids;
drop table if exists public.observability_events;
```

بعد التراجع يعود الكود تلقائيًا إلى الذاكرة (`42P01`) بلا تعديل ولا إعادة نشر.

## 6) بعد التطبيق — مفتاح الخدمة

كتابة `observability_events` تحتاج `SUPABASE_SERVICE_ROLE_KEY` على **الخادم فقط**.

- **محليًا**: أضفه إلى `.env.local` (مُستثنى في `.gitignore`).
- **في الحاوية**: مرّره كمتغيّر بيئة عند التشغيل، أو في ملف البيئة الذي يقرأه
  `docker compose --env-file`.
- **لا** تضعه في `NEXT_PUBLIC_*` ولا في Git ولا في هذه المحادثة.

بدونه: المحادثة تعمل طبيعيًا، واللوحة تقرأ من الذاكرة، ويُسجَّل رمز واحد:
`observability_persistence=disabled`.

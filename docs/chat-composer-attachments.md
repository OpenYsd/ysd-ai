# مرفقات شريط الكتابة — المرحلة 1

> النطاق: واجهة فقط. **لا تغيير** في مسار الرفع على الخادم، ولا في RAG
> (chunking / embeddings / vector RPC)، ولا في المهاجرات، ولا في `/api/chat`.

## 1. البنية كما تحقّقنا منها (قبل التعديل)

| الطبقة | الواقع |
|---|---|
| الرفع | `POST /api/files/upload` بصيغة multipart عبر XHR (`uploadWithProgress`) — **ليس** رفعًا موقّعًا مباشرًا إلى التخزين |
| الترتيب على الخادم | مصادقة ← حدّ معدّل موزّع `BUCKET_UPLOAD` (10/60s) ← النوع (امتداد + MIME عبر `resolveAllowedType`) ← الحجم ← حصّة العدد/التخزين ← ملكيّة المشروع/المحادثة ← صف `files` ← التخزين ← استخراج النص متزامنًا |
| حدّ الحجم | `getFileLimits` = الأصغر من `usage_limits.max_file_mb` (افتراضي 10) و`STORAGE_PROVIDER_MAX_FILE_MB` (50). الواجهة **لا تكتب رقمًا**: تقرأ `limits.maxFileMb` من `GET /api/files?conversationId=` |
| الأنواع | `ALLOWED_TYPES` في `lib/files/config.ts` — سمة `accept` تُشتقّ منها، فلا قائمة ثانية تتباعد. لا ZIP |
| RAG | `POST /api/files/[id]/rag` (10/دقيقة) · الحالات `ready → chunking/embedding → ready_for_rag \| rag_failed`. الصور لا تدخل RAG (بلا OCR) |
| إعادة الاستخراج | `POST /api/files/[id]/process` (15/دقيقة) |
| الإزالة | `PATCH /api/files/[id]` بـ`{conversationId: null}` — فكّ ربط، **لا حذف** |
| الروابط الموقّعة | فقط في `/api/files/[id]/download` (300 ثانية). الواجهة لا تطلبها ولا تعرضها |

## 2. الدلالة: ملفٌّ للمحادثة، لا للرسالة

الملف يُربط بالمحادثة (`files.conversation_id`) لحظة رفعه، ويدخل سياق كل رسالة
لاحقة (الاسترجاع في `lib/rag/retrieval.ts` يصفّي بـ`conversation_id` أو
`project_id`). **لا يوجد في المخطّط ما يربط ملفًّا برسالة بعينها.**

لذلك:

- البطاقة قبل الإرسال «مسوّدة» (`scope: "draft"`) داخل شريط الكتابة.
- بعد الإرسال تنتقل المسوّدات المربوطة إلى مجموعة «ملفات هذه المحادثة»
  (`scope: "context"`) خلف زرّ طيّ داخل الشريط نفسه.
- **لا يُرسم أيّ مرفق داخل فقاعة رسالة** — فالتاريخ بعد إعادة التحميل لا يستطيع
  إثبات تلك العلاقة، ورسمها ادّعاء.
- `/api/chat` لا يستقبل حقل مرفقات؛ جسم الطلب لم يتغيّر.

## 3. آلة الحالات لكل بطاقة

`selected → uploading → processing → (indexing) → ready` أو `error`.

| المرحلة | متى | الإزالة | إعادة المحاولة |
|---|---|---|---|
| selected | في الطابور (تزامن 2 احترامًا لحدّ المعدّل)، أو ينتظر `Retry-After` بعد 429 | إلغاء | — |
| uploading | البايتات تُرسل — شريط تقدّم حقيقي | إلغاء (abort) | — |
| processing | اكتمل الإرسال والخادم يستخرج | معطّلة (الصف لم يُعرف بعد) | — |
| indexing | `chunking/embedding` أو طُلب RAG | فكّ الربط | — |
| ready | صورة جاهزة · أو `ready_for_rag` · أو نصّ مستخرج بلا RAG بعد (زرّ «تجهيز») | فكّ الربط | `rag` |
| error | شبكة/5xx، أو 429 بعد ثلاثة انتظاراتٍ تلقائيّة | إزالة | `upload` (الملف نفسه) |
| error | 413/403/401/404/400 أو فشل التحقّق المسبق | إزالة | لا |
| error | `failed` / `rag_failed` | فكّ الربط | `extract` / `rag` |

- **429 يوقف الطابور كلَّه** مدّةَ `Retry-After` (بين 1 و60 ثانية) ويُعيد الملف إلى
  رأسه، فلا يُرسل باقي الدفعة إلى نافذةٍ مغلقة. لكل ملفٍّ ثلاثة انتظاراتٍ تلقائيّة، ثم
  خطأٌ بزرّ إعادةٍ يدويّة — فلا حلقة بلا نهاية.
- **الإرسال يُحجب** فقط ما دامت مسوّدةٌ في `selected/uploading/processing` — أي
  قبل أن يوجد صفّها مربوطًا بالمحادثة، فالرسالة لن تراها. التجهيز لـRAG لا يحجب.
- رسائل الخادم ثنائيّة اللغة (`عربي | English`) يُختار منها جانب لغة الواجهة.
- التحقّق في المتصفّح (نوع/فارغ/حجم) تجربة استخدام فقط؛ الخادم هو الحكَم.

## 4. مصادر الإدخال

- **منتقي الملفات**: `multiple`، و`accept` مشتقّ من `ALLOWED_TYPES`.
- **السحب والإفلات** على شريط الكتابة (عدّاد عمق يمنع وميض الطبقة؛ سحب النصّ يُتجاهل؛
  إفلاتٌ خارج المنطقة لا يفتح الملف في المتصفّح).
- **Ctrl+V**: يُلتقط فقط ما يقبله الخادم من الصور (`png/jpeg/webp` حسب
  `ALLOWED_TYPES`)، وفقط حين لا تحمل الحافظة نصًّا — لصق النصّ لم يتغيّر. تُسمّى
  الصورة `pasted-image-YYYYMMDD-HHMMSS.ext`.

## 5. الأمان

- الاسم يُعرض نصًّا في React (لا `dangerouslySetInnerHTML`) — لا حقن عبر الاسم.
- `displayFileName` يحذف محارف التحكّم C0/C1 ومحارف الاتّجاه (LRM/RLM/ALM،
  U+202A–U+202E، U+2066–U+2069) كي لا يُقرأ `photo<RLO>gpj.exe` كأنه صورة.
  ZWNJ/ZWJ باقيان لعملهما المشروع في الكتابة العربيّة والفارسيّة.
- سطر الاسم `dir="auto"` فيتبع اتّجاهَ نصِّ الاسم لا الواجهة: امتداد `report.pdf` يبقى يمينَ
  الاسم في واجهةٍ عربيّة، وامتداد `تقرير.pdf` يسارَه. الجذع `<span>` (خوارزميّة
  `dir="auto"` تتخطّى `<bdi>`)، والامتداد `<bdi dir="ltr">` منفصلًا فيبقى ظاهرًا حين يُقصّ الاسم.
- لا روابط تنزيل ولا روابط موقّعة في البطاقة.
- `conversationId` يُلتقط لكل ملف عند اختياره، ولا يتغيّر بعدها.
- **إعادة تركيب المحادثة نفسها** (محادثةٌ جديدة تصير `/chat/:id` حين يصل
  `router.refresh` بعد أول ردّ) لا تُضيّع شيئًا: التفكيك يُسلّم المسوّدات — بملفّاتها
  ورفعها الجاري وطابورها — مفتاحُها محادثتُها، ومكوّنُ **تلك المحادثة** يتبنّاها.
- **تبديل المحادثة** يعيد تركيب `ChatView` (`key={id}`) لمحادثةٍ أخرى، فتُلغى
  مسوّدات الأولى فورًا ولا تُتبنّى في الثانية؛ وما لم يتبنَّه أحدٌ خلال ٥ ثوانٍ (مغادرةٌ
  إلى صفحةٍ أخرى) يُلغى. الرفع الذي اكتمل على الخادم قبل الإلغاء يبقى في محادثته
  الأصليّة (سلوك الخادم كما كان).

## 6. خارج هذه المرحلة (موثّق عمدًا)

### رسالة بملفّ فقط
غير مدعومة: `/api/chat` يشترط `message` (min 1) إلا في إعادة التوليد، و`send()` في
العميل يشترط نصًّا. دعمها يتطلّب تغيير عقد الـAPI وموجّه النموذج — مرحلة لاحقة.

### علاقة رسالة ↔ مرفق (الهجرة المطلوبة لاحقًا)
لرسم المرفقات داخل فقاعة الرسالة **بصدق** وبعد إعادة التحميل:

1. مهاجرة جديدة (رقمها التالي بعد 0047):
   ```sql
   create table message_attachments (
     message_id uuid not null references messages(id) on delete cascade,
     file_id    uuid not null references files(id)    on delete cascade,
     user_id    uuid not null references profiles(id) on delete cascade,
     created_at timestamptz not null default now(),
     primary key (message_id, file_id)
   );
   alter table message_attachments enable row level security;
   -- select/insert: user_id = auth.uid() + تحقّق أن الرسالة والملف يعودان للمستخدم نفسه
   --                وأن files.conversation_id = messages.conversation_id
   ```
2. `/api/chat` يقبل `attachmentIds: uuid[]` (حدّ أعلى صغير)، ويتحقّق من ملكيّتها
   وربطها بالمحادثة، ويُدرجها **بعد** حفظ رسالة المستخدم وفي المسار نفسه.
3. تعديل الرسالة: يحافظ على مرفقاتها؛ الحذف الناعم لما بعدها لا يمسّ `files`.
   إعادة التوليد: لا تُنشئ رسالة مستخدم، فلا مرفقات جديدة.
4. صفحة المحادثة تجلب العلاقة مع الرسائل (RLS) وتمرّرها لرسم البطاقات في الفقاعة.
5. فكّ ربط الملف من المحادثة يُبقي سجلّ الرسالة بحالة «أُزيل من السياق».

حتى ذلك: لا ادّعاء في الواجهة.

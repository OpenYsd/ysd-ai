# Browser pilot privacy gate

## Scope

The privacy gate has two deliberately different boundaries:

- **Application, YSD, and Railway logs:** zero user identity. Never emit a user UUID, email address, access/refresh token, `Authorization` header, session object, raw allowlist value, device/user code, prompt, page/selection content, or a user identifier as a metric label.
- **Supabase privileged Auth audit logs:** minimum platform-required authentication metadata only. Supabase automatically records authentication activity such as login, logout, token refresh/revocation, and password changes. Those admin-only audit records can contain actor/user identifiers and request metadata. They are not application telemetry and cannot honestly be classified under an application-log "zero UUID" rule.

The server-only `YSD_BROWSER_PILOT_USER_IDS` value is authorization configuration, not telemetry. It may be compared in memory and used as an internal database foreign key, but it must never be printed, returned in a denial response, or used as a metric/tag dimension.

## Incident classification

The investigated matches originated in Supabase Auth's internal log stream:

- Normal platform-managed login, logout, callback, and token audit events contained stable actor/user metadata.
- Additional Auth Admin `GET /admin/users/{id}` audit entries were created by the privacy/soak monitor while resolving the already-allowlisted account for an internal comparison. They were not generated by the Browser Assistant application route.
- The matched records contained no access token, refresh token, `Authorization` header, session secret, or application-added metadata.
- The corresponding Railway/YSD application-log scan had zero exact pilot UUID/email matches and zero credential/header matches.

This is **platform audit metadata only**, not a YSD runtime identity leak. Routine monitoring must not call Auth Admin user-by-id merely to correlate logs: that call creates another platform audit record containing the identifier in the administrative path. Prefer aggregate checks that do not resolve or print identity. If a one-off privileged incident correlation is unavoidable, keep the comparison in memory, return counts only, and treat the resulting Supabase audit entry as expected admin activity.

## Enforcement

- Browser metrics accept only a fixed low-cardinality event vocabulary and bounded internal codes.
- The structured logger redacts credential shapes, UUID-shaped account identifiers, and email addresses as defense in depth.
- Correlation IDs are anonymous `corr_` values and are deliberately not UUID-shaped.
- Allowlist denial is the generic `pilot_not_allowed` response; no account value is included.
- Per-account rate/quota/database keys remain internal and are never emitted as telemetry dimensions.

Production activation is outside this document. A privacy investigation or test result must never re-enable the Assistant.
